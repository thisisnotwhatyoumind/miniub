# miniUB — юзербот как плагин exteraGram

![version](https://img.shields.io/badge/version-0.5.0-blue)
![platform](https://img.shields.io/badge/exteraGram-plugin-2CA5E0)
![license](https://img.shields.io/badge/license-MIT-green)

Модульный юзербот внутри exteraGram. Плагин — это только загрузчик: сам код
юзербота лежит в этом репозитории в `userbot.py`. При запуске загрузчик
скачивает файл с GitHub, проверяет SHA-256 и выполняет его внутри процесса
exteraGram. Команды пишешь в чат — юзербот подменяет исходящее сообщение
результатом.

Это не Hikka целиком: нет своего Telethon, сессий и хостинга. Используется
живой клиент exteraGram — тот же аккаунт, что открыт в приложении, и его
сетевой слой.

## Как это работает

```text
miniub-0.5.0.plugin          загрузчик: сеть + SHA-256 + exec
        │
        ▼
userbot.py на GitHub         команды, модули, store, watcher
        │
        ▼
modules/*.py                 пользовательские модули на устройстве
```

- `miniub-0.5.0.plugin` — маленький загрузчик. В нём нет логики юзербота.
- `userbot.py` — весь код юзербота. Загрузчик берёт его из
  `https://raw.githubusercontent.com/thisisnotwhatyoumind/miniub/main/userbot.py`.
- В загрузчике зашит SHA-256 файла `userbot.py`. Если файл на GitHub
  изменился, а хеш в плагине старый — загрузчик откажется запускаться.
- Модули по-прежнему лежат на устройстве и перезагружаются на ходу.

Такой схемой удобно обновлять юзербот: правишь `userbot.py` в репозитории,
обновляешь хеш в загрузчике и выпускаешь новый `.plugin`. Без обновления
хеша загрузчик не примет изменённый файл.

## Установка

1. exteraGram → **Настройки → exteraGram → Плагины → «+» → из файла**.
2. Выбрать `miniub-0.5.0.plugin` (важно: именно `.plugin`, не `.py`).
3. Включить плагин. Загрузчик скачает `userbot.py` с GitHub.
4. Написать в любом чате `.help` и отправить.

При первом запуске юзербот создаёт папку модулей и кладёт туда три
демо-модуля: `tools.py`, `afk.py`, `fun.py`. Путь смотри командой `.modpath`.
Папка по умолчанию: `Download/miniub-plugin/modules`.

Если GitHub недоступен или SHA-256 не совпал, в настройках плагина будет
ошибка загрузки. Это нормально: загрузчик специально не запускает
непроверенный код.

## Обновление

Есть два разных обновления:

- **Модули** — просто положи `.py` в папку модулей или используй `.lm`/`.ilm`.
  Плагин перезагружать не нужно.
- **Код юзербота (`userbot.py`)** — обнови файл в репозитории, посчитай новый
  SHA-256 и вставь его в `USERBOT_SHA256` в загрузчике, затем пересобери и
  переустанови `.plugin`. Либо выпусти новый релиз с готовым загрузчиком.

Хеш можно посчитать так:

```bash
sha256sum userbot.py
```

В репозитории это автоматически проверяет `tools/check_loader.py` в CI.

## Команды движка

| Команда | Что делает |
|---|---|
| `.help` | список модулей и команд |
| `.ping` | проверка отклика |
| `.mods` | загруженные модули и ошибки |
| `.modpath` | пути к папкам модулей |
| `.reload` / `.reload all` | перечитать все модули |
| `.reload tools` | перечитать один модуль |
| `.lm <имя>` | загрузить модуль из папки модулей |
| `.lm` ответом на `.py` | установить и сразу загрузить модуль из файла |
| `.ilm <url>` | скачать и установить модуль по http(s)-ссылке |
| `.ilm <имя> <url>` | то же, но с явным именем модуля |
| `.ulm <имя>` / ответом на `.py` | выгрузить модуль из памяти (файл остаётся) |
| `.dlm <имя>` / ответом на `.py` | выгрузить и удалить файл модуля |

Префикс меняется в настройках плагина (по умолчанию `.`).

### Установка модуля на ходу

Способ 1 — ответом на файл:

```text
.lm
```

Отправь `.lm` ответом на `.py`-файл. Юзербот скачает файл из сообщения,
сохранит его в папку модулей и сразу загрузит. Имя берётся из имени файла;
можно задать своё: `.lm mymod` (ответом на файл).

Файл должен быть в UTF-8 и не больше 512 КБ.

Способ 2 — скачать по ссылке:

```text
.ilm https://example.com/mymod.py
```

Имя модуля берётся из имени файла в ссылке. Если оно не подходит, укажи
имя явно:

```text
.ilm mymod https://example.com/mymod.py
```

Для GitHub нужна ссылка на **raw**-файл, а не на страницу `blob`.

Загрузить уже лежащий в папке модуль: `.lm mymod`. Выгрузить из памяти,
не удаляя файл: `.ulm mymod` (или `.ulm` ответом на его `.py`). Удалить
файл: `.dlm mymod` (или `.dlm` ответом на файл).

## Два слоя модулей

| Слой | Где лежит | Права |
|---|---|---|
| `system` | приватная папка плагина `miniub_system/` | полный доступ к движку; сюда входит `core` |
| `user` | обычная папка модулей | обычный Python-код; не может занять имя системного модуля |

Ядро (`help`, `ping`, `mods`, `modpath`, `reload`, `lm`, `ilm`, `ulm`, `dlm`) —
это обычный системный модуль `core.py`. Юзербот пересоздаёт его при каждой
загрузке.

Оба слоя выполняются обычным Python, без песочницы. Разделение чисто
организационное:

- системные модули лежат в приватной папке и не удаляются командами;
- системные команды всегда приоритетнее пользовательских при совпадении имён;
- watcher перезагружает только пользовательские модули;
- у пользовательских модулей свой namespace в `store` и нет `ctx.plugin`
  (только текст, id и `reply/send`).

Ставь только те модули, которым доверяешь: код выполняется в процессе
exteraGram с полными правами Python.

## Как писать модуль

Кладёшь `modules/mymod.py`:

```python
from miniub_api import command, on_message, store


@command("echo", aliases=("e",), description="Повторить текст", usage=".echo <текст>")
def echo(ctx):
    return ctx.args or "Использование: .echo <текст>"


@command("afk", description="Автоответчик")
def afk(ctx):
    store.set("afk", {"reason": ctx.args or "недоступен"})
    return "💤 AFK включён"


@on_message(private=True)
def reply_afk(ctx):
    state = store.get("afk")
    if not state:
        return None
    return "💤 AFK: " + state.get("reason", "")
```

Потом `.reload mymod` — или просто сохрани файл, если включена
автоперезагрузка. Всё.

Готовый шаблон: `modules/_template.py`. Файлы, начинающиеся с `_`,
загрузчик пропускает.

### Правила

- Имя файла: латиница, цифры, `_`, до 41 символа. `core` зарезервировано.
- Обработчики **синхронные**. Никаких `async`/`await`: хук вызывается из
  сетевого потока приложения, и долгая работа его блокирует.
- `@command` ловит **исходящие** сообщения: то, что ты сам отправляешь.
- Если обработчик вернул строку — она заменит текст сообщения.
- Если вернул `None` — сообщение уйдёт как есть (полезно для проверок).
- `@on_message` ловит **входящие** через `TL_updateNewMessage` и
  `TL_updateNewChannelMessage`. `private=True` — только личка,
  `private=False` — только группы, `None` — везде.
- Строка, возвращённая из `@on_message`, отправляется ответом на сообщение.
- В модуле можно объявить `on_load()` и `on_unload()` — они вызовутся
  при загрузке/выгрузке (без аргументов).

### Что есть в `ctx`

| Поле | Значение |
|---|---|
| `ctx.args` | текст после команды |
| `ctx.text` | весь текст сообщения (для команд — без префикса) |
| `ctx.account` | номер аккаунта |
| `ctx.chat_id` | id чата |
| `ctx.sender_id` | id отправителя (для входящих) |
| `ctx.message_id` | id сообщения (для входящих) |
| `ctx.module` | имя модуля |
| `ctx.command` | имя сработавшей команды |
| `ctx.reply(text)` | ответить на сообщение |
| `ctx.send(text)` | отправить в тот же чат без реплая |

### Хранилище

`store.get(key, default=None)`, `store.set(key, value)`, `store.delete(key)`.

У каждого модуля автоматически свой namespace, чужие ключи не видны.
Хранилище — JSON в приватной папке плагина, переживает перезапуск.

### Логи

`log.info(...)`, `log.warning(...)`, `log.exception(...)` — пишут в logcat
с тегом `plugin.miniub`.

### Автоперезагрузка

В настройках есть переключатель **«Автоперезагрузка модулей»** (по умолчанию
включён). Фоновый поток раз в 2 секунды проверяет mtime `.py`-файлов в
пользовательской папке и перезагружает изменённые модули. Новый файл,
просто положенный в папку, тоже подхватится. Системные модули так не
перезагружаются — только через `.reload`.

## Структура репозитория

```text
miniub-0.5.0.plugin      — загрузчик (устанавливаемый файл)
userbot.py               — код юзербота, скачивается загрузчиком
modules/tools.py         — демо: .echo, .up, .rev, .mock
modules/afk.py           — демо: .afk, .unafk, заметки .save/.note/.notes и автоответ
modules/fun.py           — демо: .roll, .coin, .ball, .pick
modules/_template.py     — шаблон модуля, загрузчиком пропускается
tools/check_loader.py    — сверка SHA-256 загрузчика с userbot.py
tools/check_embedded.py  — проверка встроенных в userbot.py модулей
tests/test_loader.py     — тест скачивания/проверки/внедрения кода
.github/workflows/       — CI: проверки и релиз по тегу v*
README.md                — этот файл
CHANGELOG.md             — история версий
SECURITY.md              — предупреждение о доверии к коду
LICENSE                  — MIT
```

Приватные данные плагина (`miniub_system/`, `miniub_data/`) создаются
рядом с установленными плагинами и вручную не нужны.

## Разработка

Проверки не требуют установленного exteraGram:

```bash
python -m py_compile miniub-0.5.0.plugin userbot.py modules/*.py
python tools/check_embedded.py userbot.py
python tools/check_loader.py miniub-0.5.0.plugin userbot.py
python -m unittest discover -s tests -v
```

`check_embedded.py` вытаскивает `SYSTEM_CORE` и `DEMO_*` из `userbot.py` и
компилирует их отдельно. `check_loader.py` проверяет, что зашитый в
загрузчике SHA-256 совпадает с `userbot.py`.

## Ограничения

- Нет своего сетевого слоя: всё идёт через текущий клиент exteraGram.
- Загрузчику нужен интернет при каждом запуске плагина: он скачивает
  `userbot.py` с GitHub. Если GitHub недоступен, юзербот не загрузится.
- Входящие обрабатываются только текстовые; медиа-события не ловятся.
- Команды работают только у владельца аккаунта (это исходящие сообщения).
- Песочницы нет: модуль — это обычный Python-код в процессе приложения.
- Долгие обработчики блокируют сетевой поток — не спи внутри команд.
  Загрузка файла из ответа тоже выполняется в этом потоке (до 30 секунд).
